# D8、D16：規則預算是否真能改善表示？

本輪日期：2026-11-03。Dn 一律指階數 **2n** 的二面體群；D8 有 16 個元素、D16 有 32 個元素。生成元順序 r、r^-1、s，右乘、單位成本，與 D4 實驗一致。

## 本輪實際比較了什麼？

1. **貼面排序累加：**先 rsrs，再 r^n。面來自合法稜柱球面嵌入，非任意把關係叫作面。
2. **一般池排序累加：**枚舉長度 3..n 的 cyclically freely reduced 閉合字，以循環位移及反向取逆去重，再按長度、字典序加入；每個 K 保存 checkpoint，直到首次有限。
3. **嚴格短關係控制：**只允許長度≤6，全部加入後檢查，不偷偷補長度 n 的旋轉關係。
4. **等原始預算控制：**固定唯一的長度4關係 rsrs，逐一搭配每條長度 n 的一般關係；每次恰好2條、總長 n+4。
5. **池內最小性：**逐一檢查一般池每條候選單獨使用時仍有活循環，再給一個2條的有限證書。這才證明指定池／規則展開內最少數量為2。

三組都含相同的相鄰逆操作消去。`K` 是 canonical 關係數，不是展開規則數，也不是所有面數。沒有使用 BFS 距離調整關係選擇。

## 結果要分三層解讀

| 問題 | D8 | D16 |
|---|---:|---:|
| BFS 直徑 D | 5 | 9 |
| 貼面順序首次有限的 K | 2 | 2 |
| 一般短到長順序首次有限的 K | 3 | 71 |
| 在同一一般池內，真正最少 K | 2 | 2 |
| 等長2條配對：有限／全部 | 1/4 | 1/144 |

因此不能說「一般關係需要71條，面只需要2條」。準確說法是：「這個一般最短優先順序直到第71條才選到需要的長關係；一般池本身也有2條就足夠的選法。」

成功的兩條關係為 rsrs=e 與 r^n=e。合用時有限接受語言恰好有 2n 個字，全部是 BFS 最短字；最長字 r^(n/2)s，故 U=D、gap=0。兩種方法在這裡的精確上界相同。

嚴格長度≤6的兩條一般關係，對兩個群都無法消除純 r 活循環。比較貼面結果時必須交代：面提供了長度8／16的關係，而短池原本就不允許使用它。

## 面究竟帶來什麼？

對這個群族，合法稜柱的面系統有 n 個四邊形與2個 n 邊形，canonical 後恰剩 rsrs 與 r^n。它提供一種稀疏選取有效關係的方法。

本次稜柱構造本身就是由人工指定的已知關係 rsrs、r^n 作 seed，再抽取其面邊界；**不是演算法從未知巨大圖自動發現這兩條關係**。所以這是一個有明確構造知識的對照，不能用來宣稱拓撲方法在公平盲選下已勝出。

但兩個嵌入 genus 都是0，直徑卻分別5與9；一般池也已包含這兩條關係。因此這輪支持**選擇策略的效用**，沒有證明 genus 的預測力或拓撲資訊帶來本質新關係。

## 如何逐步讀一個例子？

以 D16 為例：

1. 打開 `d16/source.json`：確認32個群元素與轉移表，讀 BFS `truth_paths`、直徑9，以及合法面檢查。
2. 看 `face_prefix-k001.json`：只有 rsrs，保存前綴 r、循環 r，語言無限。
3. 看 `face_prefix-k002.json`：加入 r^16，活圖成 DAG；最長字為8個 r 接一個 s，長度9。
4. 看 `ordinary_shortlex_prefix-k070.json`：一般短到長順序已加入70條，仍有活循環。
5. 看 `ordinary_shortlex_prefix-k071.json`：第71條才加入 r^16，得到 U=9，但規則數已達11105，而面組是30條。
6. 看所有 `matched-pair-*.json`：相同2條預算與總長20，144種配對只有使用 r^16 的一組有限。
7. 看所有 `singleton-*.json`：214條候選全部單獨無限，為本池最少2條提供完整有限範圍證書。

## 這種表示法是否有效？

**已示範：**從合法下降規則建立 DFA，可以不用用 BFS 直徑作輸入，就由 DAG 最長路徑取得精確的上界，再由 BFS 比對。有效的少量關係，比盲目增加大量關係更精簡。

**尚未示範：**比 BFS 更快、較低峰值記憶體、對魔方有效、一般最小關係選擇演算法或新的複雜度界。這裡只到32個群元素，BFS 很便宜；較大的 raw 規則庫還可能比直接儲存群圖昂貴。

## 成本欄位不能混讀

- `source.costs`：群建構、BFS、面建構、一般池枚舉、全池規則庫與逐候選展開時間。
- `step.costs.measured_stage_seconds`：本步取規則及分析時間。分析含全部起點的規則檢查、DFA建構／有限性、指定長度內回歸、有限字／群比較，不是純 DFA 查詢時間。
- `sequence.sum_measured_stage_seconds`：沿該排序找到第一個有限預算前，所有已測步驟的時間總和。另需計入共享前處理與檔案、獨立驗證成本。
- `expanded_rules`、`expanded_rule_symbols`：展開後實際規則成本，避免只比較 K。
- `dfa_serialized_utf8_bytes`：DFA JSON 的編碼大小，包含禁止子字與字尾標籤，不只是轉移圖，**不是峰值 RAM**。這輪沒有測峰值 RAM，也沒有重複測量後的穩定加速比。
- 實驗框架為核對全部候選，會先建全池規則庫；面策略本身不必先生成整個一般池。共用框架成本與方法必要成本必須分開，不拿此實作的單次總秒數作速度定論。

## 證據如何保存與驗證？

每輪新的 UTC 目錄包含 `results.json`、`verification.json`、兩群的 `source.json` 與每個 checkpoint。規則在群共用 `rule_library` 保存，checkpoint 使用 `rule_ids` 避免重複大量長字；原始 relators 也用 `selected_relator_ids` 指回完整 pool。

有限步保存拓撲順序、最長路徑、全部有限字與 U−D；無限步保存可達前綴、非空活循環、群的 identity block 與任意次重複的示範。無限語言沒有有限的最長字上界，`upper_bound` 與 `gap` 保存為 null，不用 infinity 冒充群直徑。

獨立驗證器以明確二面體公式重建轉移表、用路徑與邊不等式驗證 BFS、重新枚舉完整關係池、檢查面與規則來源，再驗證每步 DFA 轉移不變量、循環／拓撲證書、上界差距及完整的 singleton／等長配對集合。它不匯入本輪實驗 runner 或 DFA 建構器；仍共用既有規則展開及面檢查，不是 Lean 證明。

長度0..3的逐字回歸只是額外測試。有限性不是由短字枚舉推測，而是完整自動機圖的證書。

## 重跑

從 repository 根目錄：

```powershell
# 核心實驗與證書檢查只需標準 Python；每輪不覆蓋
python cayley-thesis/experiments/dihedral_automata.py

# 只跑 D8 做入門
python cayley-thesis/experiments/dihedral_automata.py --groups 8

# 重驗某輪（填入程式印出的目錄）
python cayley-thesis/experiments/verify_dihedral_automata.py <結果目錄>

# 五項新測試，含D16的70→71轉折與損壞證書
python -m unittest discover -s cayley-thesis/experiments -p test_dihedral_automata.py -v
```

可用 `& ./cayley-thesis/reports/dihedral-automata/run-experiment.ps1` 一鍵重跑並畫圖。畫圖選用既有 Manim 環境的 Pillow，不需要另外安裝套件。
